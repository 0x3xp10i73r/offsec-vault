# Meghan Tashi

<p class="about-role">Security Researcher</p>

<p class="about-lead" markdown>
This site is my **practical security notebook** — testing notes, lab writeups and checklists, written down clearly so they are easy to reuse during a lab, a review or an authorized assessment. I learn by taking one complicated security question and breaking it into smaller ones: *what is the application trusting, what should the user be allowed to do, what evidence would prove the problem, and how could the control be improved?*
</p>

## What I work on

<div class="grid cards" markdown>

## Featured projects

<div class="grid cards" markdown>

-   :material-flask-outline:{ .lg .middle } __An Exploitable App__

    ---

    An intentionally vulnerable full-stack web app built to demonstrate common flaws in a controlled setting — CSRF, open redirects, sensitive data exposure and missing access control — assessed manually and with tooling to prove impact.

    [:octicons-link-external-16: Published in IRJMETS](https://www.irjmets.com/uploadedfiles/paper//issue_2_february_2023/33924/final/fin_irjmets1678126362.pdf)

-   :material-notebook-edit-outline:{ .lg .middle } __Hacker Methodology Manager__

    ---

    A tool for organizing and tracking offensive-security methodologies and checklists, tagged by area (Web, AD, Privilege Escalation) with search and an offline-first design. Planned: a local database, user-defined modules and real-time sync.

</div>
